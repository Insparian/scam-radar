# Encrypted backup to Workers KV — offline contract

Decision [015](../../DECISIONS/015-isolated-cloudflare-free-account.md) selects a dedicated Cloudflare Free account as the proposed private encrypted backup destination. This adds a future outbound path: **Supabase PostgreSQL → protected GitHub Actions runner → Cloudflare Workers KV API**. The runner streams the dump through pinned `age` before upload. KV receives only random-ID ciphertext chunks, SHA-256 hashes, byte counts, and creation/scope metadata; no plaintext dump, source body, model prompt, query, or recovery identity. No real backup has been sent.

The backup clock is a separate Worker in `cloudflare/backup-scheduler/`. At 02:43 UTC it can dispatch only `backup.yml` on `main`, with `scheduled=true`; missing `SCAM_RADAR_BACKUP_SCHEDULER_ENABLED=true` makes it inert. GitHub independently requires `SCAM_RADAR_BACKUP_ENABLED=true`, `SCAM_RADAR_LIVE_ACTIVATION_APPROVED=true`, saved exact backup confirmation, scheduled switch for the scheduled path or typed confirmation for a manual path, protected `production-backup` environment, and matching dedicated account ID. This avoids GitHub's public-repository schedule inactivity rule. Dispatch acceptance does not prove backup success; inspect workflow outcome and readback.

The KV adapter is `scripts/upload_kv_backup.py`: 16 MiB chunk keys, manifest written last, SHA-256 and byte count checked before write and on readback, no blind retry after uncertain writes. Download reconstructs only into ignored `work/`, verifies every chunk and overall age ciphertext, then an operator can decrypt with offline-held identity and restore into a separate database. Live download requires `SCAM_RADAR_BACKUP_RECOVERY_APPROVED=true`. The old R2 adapter remains for the existing local S3 recovery test and historical evidence; it is no longer the production backup workflow.

Activation values: protected GitHub `production-backup` Variables `SCAM_RADAR_AGE_RECIPIENT`, `SCAM_RADAR_BACKUP_PGHOST`, `SCAM_RADAR_BACKUP_PGUSER`, `SCAM_RADAR_KV_ACCOUNT_ID`, `SCAM_RADAR_KV_NAMESPACE_ID`; Secrets `SCAM_RADAR_BACKUP_PGPASSWORD`, `SCAM_RADAR_SUPABASE_CA_PEM`, `SCAM_RADAR_KV_TOKEN`. Repository Variables `SCAM_RADAR_BACKUP_ENABLED`, `SCAM_RADAR_LIVE_ACTIVATION_APPROVED`, `SCAM_RADAR_BACKUP_CONFIRMATION`, `SCAM_RADAR_BACKUP_SCHEDULER_ENABLED` remain false/absent until distinct final approvals. The Worker stores only its separate fine-grained GitHub Actions token. No recovery identity enters GitHub or Cloudflare.

Before activation: measure actual encrypted backup size, set an approved retention/deletion rule within 1 GB, decide who holds the identity, test a complete KV download and independent database restore, confirm account Free plan and namespace permissions, and define a missed-backup/space alert. A 64 MiB per-backup cap is a fail-closed guard, not proof that 1 GB lasts indefinitely. No automatic deletion is implemented; once storage fills, the job must fail and escalate instead of silently dropping a backup.

Stop: set GitHub `SCAM_RADAR_BACKUP_ENABLED=false` and Worker scheduler switch false or revoke its token. No deletion occurs from the stop action. Never paste API tokens or age identity into chat or Git.
